Blurry product images?
Check pixels before compression.

A quick diagnostic

  1. Keep the original. Check whether it is sharp before changing a whole catalog.
  2. Inspect what is delivered. In browser developer tools, inspect the image element's currentSrc, srcset and sizes. Open the selected resource and check its actual pixel dimensions. A width in a URL is only a clue.
  3. Compare pixels with display size. An image shown at 800 CSS pixels on a 2× display suggests about 1600 source pixels as a useful adequacy check—not a universal target or guaranteed fix.
  4. Check the theme before recompressing. If the delivered source is undersized, inspect the responsive candidates and layout settings. Back up the theme before any authorized edit.
  5. If dimensions are adequate, check other causes. Compare source blur, delivered encoding, CSS scaling and cropping. Test one image first.

The smaller-file surprise

Our original lossless diagram PNG was 28,431 bytes—smaller than either full-size JPEG. Text-heavy graphics can behave differently from photos. Switching formats blindly can increase file size.

There is no universal under-100-KB rule. Consider display needs, upload limits and actual page performance. A smaller uploaded file alone does not prove that the live page is sharper or faster.
